所有事件因子都把大盘科技(NVDA/AAPL/META/GOOGL)塞进组合，挤掉了动量更强的半导体/存储股。

## 根本原因：数据质量，不是算法

1. **71% 的事件是笼统的 "positive"**（796/1123），本质是噪音
2. **只有 1.2% 是真信号**（14条 upgrade/downgrade/price_target）
3. **LLM 抽取太宽松**：把"提到公司"就标成 positive，不区分"分析师上调评级"和"公司被提及"
4. **仅 2 个月数据**：异常关注度需要 6+ 个月基线，现有数据无法计算
5. **提及频率与市值正相关**：NVDA 100次 vs SNDK 9次，事件因子变成"追大盘"

## 要让星球事件因子真正有用，需要

### A. 改 LLM Prompt（最关键）
- 当前 prompt 太宽松，导致 71% 标 positive
- 新 prompt 应只抽取：明确的上调/下调评级、目标价变动、首次覆盖
- 不抽"公司被提及""文章提到某公司"这种噪音
- 预期效果：强信号比例从 1.2% -> 15-20%，给算法足够数据

### B. 6+ 个月历史数据
- 异常关注度需要时间基线
- 星球 API 只给 3 个月，需换源或攒够时间

### C. 用作负向过滤而非正向选股
- 保留动量 top 15，用事件因子踢掉负面的 5 只
- 不让事件因子往组合里塞大盘股

## 现有最优组合不变

| 因子 | OOS 夏普 | 用途 |
|------|--------:|------|
| 纯动量 | 0.57 | 主仓 |
| 动量+IMA词频(60/1.2) | 0.54 | 影子仓 |
| 星球事件(任何优化) | 0.52-0.57 | 不用 |

## 结论

算法层面已穷尽（4 种方法都试了），瓶颈在数据质量。下一步应该改 LLM prompt 重新抽取，而非继续调算法。
